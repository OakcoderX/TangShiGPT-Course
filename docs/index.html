课前 · 10 分钟

先让已经训练好的模型写一首

你只需要能运行几行 Python 命令。下载完整包后，在终端进入项目根目录。先装依赖，再加载已有权重。电脑没有 GPU 时也可以跑。

python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m tangshi generate --weights weights/more_2400_li.safetensors --form seven --prompt 江上送故人 --seed 42

Windows 的激活命令见 README。如果只下载了 GitHub 源码，从 Release 取权重放进 weights/。完整 ZIP 已附两份权重与词表。

开场讨论 · 一首四句都写满七字的作品，要通过什么检查，才会被你认作一首好诗？先写下答案，第 8 章再回来比较。

01 · 数据清洗 · 20 分钟

原始资料怎样变成训练文本

在原始 JSON 里，一条记录有作者、题名和分段正文。先拼正文，再按历史规则清掉夹注、校勘和过短残片。作者字段另外保留作李白筛选依据。

python scripts/prepare_data.py

项目实际使用的 58 个 原始 JSON 文件清单有 57,607 条记录。提取有正文的记录得到 57,603 首，清洗后保留 56,937 首。项目随包提供的清洗文本可以用此命令逐字节重建。

清洗前  邏人（一作「叉」）橫鳥道，江祖出魚梁。
清洗后  邏人橫鳥道，江祖出魚梁。

练习

打开 清洗规则，解释为什么 [煙] 会留下「煙」，较长的方括号内容会被删掉。找一条规则可能误删正文的情况。

参考答案

单字方括号有可能是编者补字，历史规则保留。括号里的文字也可能是诗句的一部分，机械删除会误伤。发布数据时应保留原始快照，方便审计和改规则后重跑。

02 · 字符与样本 · 18 分钟

每个字都是一次预测目标

字符级模型把每个字和标点映射到整数。历史词表用排序后的字符编号，最后留一个起止标记。举例中把起、止写成两种显示名称，实际代码可复用同一个编号。

原序列   起 月 下 聞 松 止
输入 x   起 月 下 聞 松
目标 y   月 下 聞 松 止

python scripts/next_char.py --char 月

频数程序只看眼前一个字，GPT 可以利用前面整个窗口。对同批不同长度的诗，填充位置只为凑整齐的张量，目标用 -100 屏蔽，真实的结束符仍参与训练。

练习与答案

如果把所有起止标记都当作填充屏蔽，模型是否收到「该停笔」的正例？不会。历史版本的停笔问题就与这个区别有关。

03 · 原理 · 30 分钟

注意力看前文，输出层给下一个字打分

Karpathy 的 microGPT 把整套计算压缩在一个纯 Python 文件里。本课程的 PyTorch 教学实现 让你在同一段代码里找到对应部件。

  1. Embedding 把字的编号查成向量，加上所在位置的向量。
  2. 因果注意力 用查询 Q、键 K、值 V 从当前位置及更早的字符里聚合信息。训练时遮住右边，避免提前看到答案。
  3. MLP 和残差 对每个位置的向量再做变换，把变换后的结果加回原向量。多个 Block 可以堆叠。
  4. 输出与损失 输出层给词表每个字一个分数。交叉熵衡量模型给真实下一字的概率，反向传播计算参数应往哪里改。

一处真实下一字的概率从 0.10 提高到 0.50，损失 −ln(p) 约从 2.30 降到 0.69。预测更准时，这一处损失更低。

练习与答案

「月下聞」里，「下」这一位置能用「聞」算注意力吗？不能。它要预测右侧的「聞」，只可以看自己及左边的「月」。

04 · 从头训练 · 27 分钟

让一个小 GPT 学会续写

每步抽一小批诗，前向计算损失，反向求梯度，AdamW 更新权重。课堂版先去精确重复，再固定种子留出验证诗。保持验证诗只用于观察。

python -m tangshi train --data runs/lesson-data/tangshi_clean.txt --limit 2000 --context 48 --width 64 --layers 2 --steps 200 --output runs/student.pt
python -m tangshi generate --weights runs/student.pt --form five --seed 42

启动时会列出可用诗篇和词表，训练结束打印验证损失并保存权重。课堂权重还包含模型结构和词表。200 步用来观察流程，输出仍会生涩。

练习

用同一语料和种子，另做 50 步和 200 步。记录训练损失、验证损失和同一个种子的诗。分别保存到不同文件。

判断提示

训练损失下降说明模型更贴合抽到的样本。若验证损失上升，要留意泛化退步。即使两者都降，仍需直接读诗，判断人物、场景和收束是否连贯。

05 · 层数、宽度与硬件 · 20 分钟

多堆几层和加宽向量是两种改法

层数是 Block 的数量。宽度是每个位置向量的长度。头数决定注意力分成几路。一次实验只改变主要变量，记下步数、数据量和验证表现。

python -m tangshi train --limit 2000 --context 48 --width 64 --layers 4 --steps 200 --output runs/student-depth4.pt

Mac 的课堂入口可以用 PyTorch MPS。项目的进阶实验使用 M5 Pro 上的 MLX 和 BF16。若想查看实际宽度实验的训练入口，见 MLX 进阶说明。

06 · 推理 · 18 分钟

抽一个字，接回前文，再继续抽

推理时逐字抽样，权重保持原样。降低温度通常会让分布更集中。固定种子可以把同一环境中的抽样过程重放。自然模式由模型决定何时遇到结束符，定长模式由程序限制每句字数并放入标点。

python -m tangshi generate --weights weights/model_base.pt --prompt 月下聞松聲 --form five --seed 42
python -m tangshi generate --weights weights/more_2400_li.safetensors --prompt 月下聞松聲 --form natural --seed 42
练习与答案

用相同权重比较温度 0.4 和 0.9。低温通常更偏向高分字符，也可能更重复。固定五言四句只验证字数和标点约束，押韵、平仄、立意需要另查。

07 · 后训练与对照 · 25 分钟

从已有权重开始，用新目标继续学习

后训练从已保存模型出发，用选定语料和较小学习率更新。模型结构和词表保持与父权重一致。为了比较后训练前后，留住两份文件，在同样的题目与种子下生成。

python -m tangshi train --init runs/student.pt --data data/tangshi_李白.txt --steps 100 --lr 0.0001 --output runs/student-li.pt
python -m tangshi generate --weights runs/student-li.pt --form five --seed 42

数据中的「李白」来自上游署名。教学程序会报告因词表不覆盖而跳过的诗。想比较两版，请用双方词表都覆盖的题目，把模型名隐藏后再读。历史权重始终留在 weights/。

练习

定两道没用于调参的新题，每道用两个种子。给每首记录三个独立判断：人物行动接得上吗，情绪有推进吗，结尾有收束吗？允许难分。最后才揭晓来源。

08 · 项目复盘 · 22 分钟

唐诗 GPT 做成了，李白 GPT 没有过线

历史项目从 Karpathy 的名字生成改成唐诗续写，随后试了扩层、加宽、李白后训练、情志句加权、直接权重探针，以及先构思再写。不同实验的训练数据和指标各自有边界。

实验课堂上可检验的结果
结束符监督修正后有模型能在句末自行停笔。
专项前的 512 维最后两批相关盲评分别相对胜出 7/24；256 维各 4/24。
选诗上限72 首中 3 首同时过行动、情绪和结尾门槛。6 题无一在两批均过线。
构思条件训练换人物选择后文字变了，6 题无一在两种子下完整跟随两种选择。

项目结论 · 能生成唐诗形式的草稿，还不能稳定写出李白风格。固定文本损失、形式合格和文学质量要分开报告。课上盲评为小样本，历史文学评分也由同一助手完成。项目结案与实验索引
